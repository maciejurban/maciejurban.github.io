# maciejurban.github.io

Personal site: a small number of deep case studies about B2B HR-tech product
design, plus short essays. Astro, static output, deployed to GitHub Pages.

**Phase 1.** The information architecture is complete and every route works;
the words are still `TK`. See [`DESIGN-NOTES.md`](DESIGN-NOTES.md) for the
design system and the reasoning behind it.

---

## Run

```bash
npm install
npm run dev          # http://localhost:4321 — drafts visible, /keystatic available
```

| Script | Does |
|---|---|
| `npm run dev` | Dev server. Drafts render. Keystatic admin at `/keystatic`. |
| `npm run build` | Static build into `dist/`. Drafts excluded, no Keystatic, no JS. |
| `npm run preview` | Serve `dist/` locally — this is what GitHub Pages will show. |
| `npm run check` | `astro check`: types and template diagnostics. Must be clean. |
| `npm run sync-fonts` | Re-copy woff2 files out of `@fontsource*` into `public/fonts/`. Only after a font bump. |

Node 22+.

## Add a case

Create `src/content/cases/<kebab-slug>.mdx`. **The filename is the URL** —
there is no `slug` field in the frontmatter, deliberately, so the two cannot
drift.

```mdx
---
title: Designing a workflow that changes while you use it
tension: One sentence. Lead with the problem, never the product.
kind: full          # 'full' | 'mini'
order: 1            # manual sort in the index; also rendered as the case number
role: What I actually did
period: 2025–2026
context: Javelo (Tellent), B2B HR-tech SaaS
themes:
  - history-as-truth
  - flexibility-cost
relatedEssays:
  - publish-dont-sync
status: draft       # 'draft' | 'published'
summary: Two or three sentences. Card text and meta description.
updated: 2026-08-25
---
```

`themes` is a **closed vocabulary** validated by a Zod enum in
[`src/content.config.ts`](src/content.config.ts). An unrecognised theme fails
the build rather than silently creating a one-item category. The six are:
`history-as-truth`, `ownership-and-teams`, `flexibility-cost`,
`medium-that-ships`, `ai-and-structure`, `semantics-before-ui`.

### The seven beats

A full case body is built from `<Beat>` sections. **Bodies start at `n={2}`** —
beat 1 is the tension, rendered from frontmatter in the page header, so the hook
has exactly one source. The beat rail is generated by reading the `<Beat>` tags
out of the body, so it can never drift from the content.

```mdx
<Beat n={2} title="The base model">

Prose.

<Artifact caption="What the reader is looking at." ratio="16/9" />

</Beat>

<Beat n={7} title="What I'd do differently" final={true}>

Always last. `final` breaks the spine and moves the beat onto a sunk surface.

</Beat>
```

Four components, and only four: `<Beat>`, `<Artifact>`, `<Aside>`,
`<Pullquote>`. They are passed in by the template, so MDX files import nothing.

Mini cases skip the beat scaffolding — a short case is a single turn of an
argument, not a compressed seven-part one.

## Add an essay

Create `src/content/essays/<kebab-slug>.mdx`.

```mdx
---
title: Publish, don't sync
dek: The argument in one sentence.
published: 2026-06-02
themes:
  - history-as-truth
relatedCases:
  - flexible-reviews
status: published
# readingTime: 6    # optional; computed from the body when absent
---
```

Essays may use `<Aside>` and `<Pullquote>`.

**Write them as block elements** — tag on its own line, blank line around the
content:

```mdx
<Aside>

The counter-argument.

</Aside>
```

On a single line, MDX parses them as inline JSX and Keystatic refuses to open
the entry ("mdxJsxTextElement has unexpected children").

## Drafts

`status: draft` items render in `npm run dev` and are absent from `npm run
build`. The filter lives in exactly one place —
[`src/lib/content.ts`](src/lib/content.ts) — and every read of a collection
goes through it, including the RSS feed and the related-entry resolver, so a
published page can never link to something that does not exist in `dist`.

## Editing in Keystatic

```bash
npm run dev
# → http://localhost:4321/keystatic
```

Local storage mode: edits write MDX straight into `src/content/`, and you
commit them like any other change. **The admin route is dev-only.** Keystatic's
UI needs a server and GitHub Pages is static-only, so the integration is
registered only when `astro dev` is running and there is no `/keystatic` in
`dist`.

`src/content/site/profile.json` (name, contact, links) is not in Keystatic —
five values edited about once, closer to configuration than content.

## Deploy

Push to `main`. [`.github/workflows/deploy.yml`](.github/workflows/deploy.yml)
builds with `withastro/action` and publishes with `actions/deploy-pages`. Pages
is configured with **Build type: GitHub Actions** (not the legacy branch build).
`workflow_dispatch` is enabled for a manual re-run.

`public/.nojekyll` is required — without it GitHub Pages drops the `_astro/`
directory, because Jekyll ignores underscore-prefixed paths, and every
stylesheet 404s.

### Custom domain

Not set up. When it is: add `public/CNAME` with the bare hostname, change
`site` in `astro.config.mjs`, and set the DNS records at the registrar. The
workflow does not need to change.

## Gotchas

### The base path

This is a **user site**, served from the domain root, so `base` is `/` and
[`href()`](src/lib/links.ts) is nearly a no-op. That is exactly why it exists.

**Never hand-write an internal `href="/work"`.** Route everything through
`href()`, `caseHref()`, `essayHref()` or `ROUTES`. If this repo ever moves to a
project path, a hand-written link 404s under the base and *nothing in the build
complains* — it is the single most common way this class of site breaks. With
the helper, it is a one-line change in `astro.config.mjs`.

One place CSS cannot use the helper: the three `url()`s in
[`src/styles/fonts.css`](src/styles/fonts.css). Update them by hand if a base
path is ever introduced.

### Phase 1 is `noindex`

Placeholder copy is publicly reachable so that every route exists in `dist` and
can be clicked, but it has no business in a search index. `IS_PLACEHOLDER_CONTENT`
in [`src/lib/site.ts`](src/lib/site.ts) adds `noindex, nofollow` to every page
and makes `robots.txt` a blanket disallow. **Flip it to `false` in Phase 3.**

### TypeScript is pinned to `^6`

`astro check` needs a programmatic compiler API that the native TypeScript 7
compiler does not expose yet. Remove the pin once it does.

### Fonts are vendored, not imported

The woff2 files in `public/fonts/` are copies made by
[`scripts/sync-fonts.mjs`](scripts/sync-fonts.mjs) from the `@fontsource*`
packages, and they are committed. The built site makes no external font
request and CI never depends on a font host. Re-run the script after bumping
either package.
